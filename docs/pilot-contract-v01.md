# Bounded pilot contract

This candidate is ready for separately authorized pilot preparation, not a
recommended release or declaration of adoption. It is suitable for one established
personal product and one lightweight personal experiment whose owners can supply
the trusted-local and recorded-review boundaries. No consumer is identified or
modified by this public contract. Eligibility, owner, exact pilot revision and
scope are confirmed in each later adoption assignment.

The source commit and digest are reviewable candidate identities, not automatic
approval of a publisher or installation. The owner approves both through a trusted
route and explicitly installs the local ZIP with the [README](../README.md) sequence.
To reproduce its exact bytes, build from that source commit in a clean trusted
checkout. Rebuilding another commit creates another candidate identity even if its
runtime files are unchanged. No release tag or hosted artifact has been published.

The smallest adoption change accepts one config, one lock and references to existing
local instructions. The owner maps **all** existing required checks/review routes,
actual command effects, state/credential isolation, provider permissions/disclosure,
integration/adjudication and representative product evidence. Existing stronger
gates remain binding. The runner validates configured requirements, not natural
language instructions; completeness of that initial mapping is an owner obligation.
The product pilot retains every required local/cloud review; the experiment retains
its protocol, output inspection, uncertainty and any human evaluation. Tool tests
or coverage labels cannot establish domain accuracy.

For the representative change:

1. Pin full accepted base/head identities. Run `doctor` through the approved
   outside-target launcher; retain its exact context and declared effects.
2. Use all existing independent permitted review routes, with their actual enforced
   tools/paths/network and disclosure. Obtain the outside-target recorded-v1 envelope
   and independently approved digest. Do not disclose private source/media merely
   to obtain a complete-looking response; unavailable evidence remains incomplete.
3. Run `check`, adding `--execute-trusted` only for explicitly trusted changes under
   the accepted owner-approved wrapper and existing effects authorization. Unknown
   provenance cannot execute. A worktree/disposable export is not containment.
4. Keep the unique local report/logs private; commit only a sanitized exact-tree
   evidence summary through the consumer's normal independent integration gate.
   Demonstrate the affected workflow/output separately where the command results
   do not cover it. Check that the tested/reviewed tree is the integrated tree.
5. Report mapped, partial and verified adoption separately. Missing local gates,
   product evidence, permission enforcement or unsupported capabilities prevent a
   verified adoption claim. Consumer exceptions need their existing authority;
   this schema has no mandatory-policy waiver mechanism.

The first implementation deliberately provides explicit-target lookup, offline
pinning, POSIX trusted-local checks and external review attestation validation.
It does not register harness slash commands, discover PRs, enforce untrusted
containment, launch reviewers, authenticate/sign attestations, prove live-review
accuracy, fetch withdrawals, publish releases, edit consumers, post, fix, merge,
restart apps or deploy. Those remain separate scopes. Cache rollback selects a
previously approved artifact and records why; source/policy changes require fresh
review, a new artifact identity and an explicit consumer pin update.
