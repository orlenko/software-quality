# Pinned inspection setup for the toolkit itself

Accepted after independent design critique, 2026-11-03. Baseline:
`0124cfcdc345bd631e83ab6f776186893d3f155c`.

Problem: this repository exercises packages in disposable subjects and follows its
manual development rules, but has no accepted consumer config/lock of its own.
That is partial process dogfooding, not its own pinned workflow.

Observable acceptance is a real schema1 config and exact approved R2 lock,
documented outside-target invocation, verified separated installation, and actual
doctor/inspection-only check evidence tied to committed setup and final integrated
source. Required target checks and authentic reviewer evidence remain incomplete.
Configured, installed, metadata-executed and fully verified adoption are distinct.

The smaller documentation-only alternative leaves no actual accepted pin. A new
wrapper or policy engine is unnecessary: use the existing explicit launcher.
No adapter installation, slash registration, new dependency or runtime change is
needed. One maintainer owns setup/integration for the canonical repository across
checkouts; completed author branches and other project work are preserved.

Responsibilities stay separate. Target source owns `.quality/config.json`, its
lock and project gate/effect/gap notes. A separately approved outside-target R2
bootstrap and archive inspect it. The setup head never chooses a head-side
launcher or becomes the archive build source. Existing manual development and
integration rules remain binding; this initial data/documentation change grants
no exception for later implementation or runtime enablement.

The config requires the full `python3 -I -S tools/test.py` discovery suite, without
selection or skip flags, and one distinct recorded-v1 source review route.
`trusted_local: false` and `isolation: unavailable` disable target execution.
The configured enforced boundary is a requirement, not an observation of an
available reviewer. No synthetic response, independence claim or approved review
digest is created. The new source reviewer remains unactivated and unqualified
for live account/model/identity/independence/context use.

The lock adopts core0.1.2/policy0.1/schema1 from R2
`db120201d3f38d1c6e444bc4d1ca9586c3d8eee0`, artifact SHA-256
`7b87b9c23fbaf43941729f8bb2b0e1969fbf6872b02d8dbd23e074714bc526b0`.
Keep all original/interim/new archives and A2 unchanged. No rebuild, requalification
or pin/state migration follows from adoption.

Data effects are newly owned private outside-target sibling bootstrap, cache,
state and evidence directories. Extract the two approved R2 bootstrap blobs and
copy existing archive bytes only after matching independently approved hashes.
Offline install writes a digest-named immutable cache entry. Doctor and check
without execution inspect Git/config/lock/pin metadata and run only the approved
benign process-capability probe; reports and locks stay outside the target.
No target imports/tests, private inputs, real credentials, provider or network
inference are needed. Future target execution requires exact trusted interpreter,
dependency/import/effects approval or actual containment for unknown provenance.

Bad source/digest/schema/path/runtime capability refuses without fallback,
provisioning or rebuilding. Expected doctor/check result is incomplete/2: full
checks are unexecuted and authentic review is missing. A definite failure would
still take precedence. Git-free snapshots cannot supply actual-index/privacy
evidence; no fake index, private skip, subset-as-full-gate or relaxed600s bound is
accepted. Release, packaging qualification, live review and full adoption remain
separate required decisions/evidence where applicable.

The test plan is factual/static verification, actual pinned install and metadata
inspection. Independently review the exact initial setup delta against baseline
0124 BEFORE the owner designates its committed config/lock as bootstrap accepted
base. A `base=head` report is metadata-only: its empty changed-path list does not
review that delta. Check report context/config/lock/tool identities, pin/inspection
stages, disabled check/snapshot/output stages, missing reviewer and exit2. After
normal reviewed integration, bind metadata to the actual integrated head and clean
state, keeping the separate delta review. A documentation evidence leaf receives
its own affected review. No runtime suite/build is claimed for this config change.

Independent critique accepted the design with two requirements now incorporated:
initial setup acceptance precedes bootstrap-base inspection, and native reviews
never become recorded-v1/enforced/independent facts. The full source suite, including
controller offline tests, remains unexecuted for this adoption target; earlier
artifact or source counts do not transfer. Native design/finished reviews use
observed source inspection, not a mechanically enforced reviewer attestation.
Publish sanitized source IDs/digests/stage reasons only; retain outside paths and
raw reports privately. The reviewer executed no source, imports, tests, APIs or
Git writes. See the [project runbook](../toolkit-self-adoption.md).
